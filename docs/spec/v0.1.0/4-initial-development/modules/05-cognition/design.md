<a id="cognition-decisions"></a>

## 已确认的初版认知维护方案

2026-10-10，用户接受初版最小维护方案，要求参考 OpenMAIC Skill，以能用自己的话讲清概念作为理解证据；随后明确删除遗忘曲线，改为基于用户历史回复情况对理解做大致估算。本节为当前决定；此前遗忘预测、参数持久化、按需计算和校正方案均被本次决定替代。

### 理解状态

沿用知识点 example 的组织，分别用文字描述解释、应用、迁移表现，关联依据和实际帮助条件；缺少证据时表达未知。初版不设总掌握分或固定等级，也不为判断增加量化阈值。关系中的认知判断沿用其 example，描述用户对具体联系的表达、理解与应用，不要求填满所有维度。

### 理解假设

Agent 根据新旧证据新增、修订、合并或撤回假设：同义假设复用记录，竞争解释可以并存，支持与反对证据分别关联。被推翻的假设保留历史与原因，不抹去旧判断；没有有区分力的新证据时保留未决。初版不设置信度公式、自动淘汰阈值或额外生命周期状态机。

### 基于历史回复估计理解

Agent 综合用户在相关知识点或关系上的历史回复、解释、理由、实际应用与纠错，大致估计当前理解，附来源和帮助条件。新的表现用于支持、修订或保留原判断；历史表现相互冲突时保留相关证据和竞争解释，不仅凭最后一条回复覆盖旧判断。没有相关表现时表达未知，没有新证据时保留现有判断。

时间记录用于理解表现发生的顺序与条件；时间经过本身不自动降低理解状态。初版不设置遗忘曲线、半衰期、预测参数、回忆概率或数值校正规则。

<a id="understanding-evidence"></a>

### 理解证据与判断更新

2026-10-10，用户明确“能用自己的话把一个概念讲清楚就表示已经理解了”。初版据此把用户用自己的话正确说明概念核心含义及必要机制，作为当前解释维度已经理解的有效证据；Agent 根据实际表达判断，不要求固定术语、额外考试或完整费曼练习循环。应用与迁移仍根据对应实际表现维护。

解释前是否看过说明、是否获得关键提示作为帮助条件保存。讲解后的清楚解释可以支持当前理解，不反推讲解前已经理解；后续独立解释或应用作为新的历史表现，帮助修订理解判断。表达中的具体缺口或错误用于修订相关理解假设；提示后完成单独记录其条件，没有回应继续保持未决。

本次按已登记的本地路由核对 OpenMAIC 提交 `c72a64b4b669608bd682ae561bea0e059710930a`：

- [费曼学习法](E:/JourneyIntoAI/DL_and_LLM/projects/OpenMAIC/skills/agent-runtime/feynman-learning/SKILL.md)：以学习者解释为核心，检查因果缺口、术语替代、类比边界与迁移；DistillAI 借鉴证据判定，不照搬课堂循环。
- [理解本位设计](E:/JourneyIntoAI/DL_and_LLM/projects/OpenMAIC/skills/agent-runtime/understanding-by-design/SKILL.md)：通过理由、实际任务和新情境表现判断理解。
- [最近发展区](E:/JourneyIntoAI/DL_and_LLM/projects/OpenMAIC/skills/agent-runtime/zone-of-proximal-development/SKILL.md)：真实作品可作证据，独立与受助表现分开，判断保留实际任务与支持条件。

本模块借鉴这些 Skill 的理解与表现证据规则，由 Agent 根据实际历史回复形成大致判断；正式分析 Prompt 留到最后一轮。

### 更新入口与范围

episode 分析、MCP 反馈和用户纠错作为同一认知维护流程的证据输入。日常交流中的回忆、解释和实际应用沿既有表现规则处理，不需要 Web 复习入口。只更新有直接依据的知识点或关系；同一次表现不重复计入，不沿知识关系自动传播掌握判断。知识正文变化本身不代表用户理解变化。M04 没有新增知识内容时，仍可由 M05 分析已有知识点上的新用户表现。

必要交接只补清证据输入、判断输出及来源关联：M03 提供 episode 与原始来源，M04 提供已有知识、关系及维护结果，M07 提供实际表现、帮助条件与纠错，M08 提供信息查看及用户明确纠错的入口，不提供复习交互；M05 向 M06–M08 提供有依据的理解状态、相关假设和用户表现。保存、版本、冲突恢复沿 M01，记录组织沿 M04 的 example；MCP / Web 表达分别由 M07 / M08 定义。

### 记录与来源交接

沿现有 example 保存 observations / hypotheses / cognition / changes：观察保留用户实际回复或产物、发生时间、任务、来源与帮助条件；假设保留主张、当前处理状态、支持 / 反对证据和仍需区分的问题；理解判断保留评估时间、文字描述及对应观察 / 假设引用。状态与结果文字表达实际情况，不新增评分器或固定大枚举，没有材料的分组允许为空或省略。关系沿其 example，跨关系假设继续只保存外部引用，不复制正文。

episode 分析保留 episode 与版本、真实来源及相关已有知识 / 关系，不能只把 M04 新增结果作为认知分析输入；M04 空结果仍允许结合原材料查找已有知识并记录新表现。MCP 反馈保留实际用户表现与帮助条件，Web 明确纠错保留用户提交内容及所纠正的记录版本，均关联可回查来源；实际字段在 M07 / M08 对齐时沿用这些语义。更新结果为实际修改的知识点 / 关系引用及原因；无新增证据或无需修改时允许成功空结果，不强制生成观察或假设。

同源 Hook / MCP 表现只维护一份观察，以原始来源关联已有记录；新的表述或表现另行判断，不把重复交付当新证据。必要引用与结构校验、记录版本、历史、任务提交和失败恢复沿 M01 / M02 / M04，检查观察与假设引用可定位且认知修改保留知识正文、关系端点及来源；理解是否成立由 Agent 判断。校验失败返回修正，超出既有额度沿 M01 失败处理，不另建异常状态机。

#### 认知地图与能力蒸馏目标

2026-10-05，用户明确项目目标：通过 episode 等材料持续拟合用户认知地图，在其基础上向外搜索有依据的知识连接，通过 Prompt 注入和日常交互帮助用户建立新连接，再用新增表现修订地图，重复这一循环，逐渐将 AI 能力蒸馏给用户并改善协同。传统 Agent 记忆与 LLM Wiki 提供资料组织方面的参考，但不定义本项目的完整目标。能力增长是待通过实际表现验证的产品假设，不能以图规模或注入次数替代。

用户提出区分知识点之间确实存在的联系与用户通过联想建立的关联，例如 vLLM batching 与项目任务调度器。以下保留历史建模输入；当前关系结构与字段归属沿已批准 M04，理解估计沿本模块前文，不重新提出同一抉择：

- 分别记录关系内容的核查状态和用户对关系的表达、理解及应用证据。同一对知识点可同时存在知识关系与用户联想；观察到联想不自动证明联想成立，联想错误也不应从认知记录中抹去。
- 从同一组记录形成有来源依据的知识关系视图与有用户证据的认知视图；外部发现但用户尚未表现出理解的关系属于扩展候选，不自动计入用户已建立的连接。不预设两套独立存储。
- 边元数据候选：稳定 ID、两端知识点、关系类别与方向语义、具体关系陈述及适用条件、来源与提出者、内容核查状态及依据、关联用户观察与理解假设、首次与最近更新来源及修订历史。类比额外记录对应点与不适用边界。
- Prompt 交付、AI 实际采用、用户接触和用户独立应用分别记录，并可由边引用相关交互记录。注入后的助手解释不能回流成为用户掌握证据；重复暴露也不等于新验证。
- 图用于查找有依据的邻居、先备关系与候选连接路径，并结合用户证据和当前任务选择扩展候选。最短路径不自动等于最合适的学习路径，不混用事实可信度、联想频率和理解判断作为一个边权。

完整功能范围已由 Q01 确认。外部扩展的时机与成本、交互引导选择，以及用户独立应用和跨情境迁移的证据契约，继续在 Q08 / Q10–Q15 细化。

<a id="natural-validation"></a>

### D06：日常交互与反馈

状态：`confirmed`。

#### 自然验证与选择规则

检索上下文与验证假设是不同动作，拿到假设不要求当轮验证。以完成当前任务为先，优先利用用户已有解释、选择、代码和实际应用；追问同时有助于任务且能区分假设时，才自然提问。没有机会或新增证据时保持待验证。

用户无感指无需逐次操作后台查询或查看假设与验证目的，交互继续围绕原任务。问题保持中立，不透露目标答案或诱导赞同，实际提供的帮助与表现一起记录。纠错和有区分力的新表现可通过 MCP 回写，由后台综合更新。

2026-10-08，用户进一步明确日常交互中的引导形式：通过改变助手原本需要给出的回答，使用相关类比、例子和机制说明，让用户有机会在下一条自然 Prompt 中呈现自己的认知。例如交流已提到调度器时，助手可以酌情借 vLLM 调度器解释工作组织，用户可以继续任务、追问术语、认可连接或补充自己的理解。日常回应保持原任务的节奏，额外解释、练习或复述任务只在用户需求和当前任务本身需要时安排。

反馈解释保留不同可能：追问“什么是 vLLM 调度器”支持对该名称或具体机制尚不清楚的假设，仍需结合问法及后续表达；没有相关回应可能是未注意、已了解、不想展开或仍聚焦任务，不能据此判断掌握或不懂；“这个类比很好”可以记录为用户认可或主观感到帮助，尚不足以确认此前没有该联系、现在已能独立应用。用户主动说明对应点、指出边界或在后续任务中自行使用时，分别记录为更具体的理解表现。助手已经给出的解释与类比属于帮助条件，不能将之后的认可当作帮助前的独立理解证据。

选择规则候选先考虑任务相关性和打断成本，再考虑区分力、关键依赖与有效覆盖。其他条件相近时，覆盖更多当前相关概念的假设可以优先；关联五个知识点不表示一次验证确认五个知识点的掌握。

#### 螺旋操作符与费曼交互方法

2026-10-08，用户明确 `spiral-curriculum` 的主要参考价值是渐进式、多维的理解发展方法：用操作符选择从哪个维度验证或加深某个知识点的理解，也用于判断外部候选能带来什么学习增量。具体课程创建和固定学习路线不作为本项目的运行契约。

结合外扩候选的连接价值、用户认知待验证问题和当前任务选择适当维度：`ADD_RELATION` 检查或建立概念联系，`ABSTRACT` 检查或形成共同机制，`FORMALIZE` 引入或检验形式化表达，`CHANGE_REPRESENTATION` 改换表征，`ADD_COMPLEXITY` 增加变量与相互作用，`ADD_EXCEPTION` 检查或补充边界，`INCREASE_TRANSFER_DISTANCE` 关注新情境应用。一次交互选择相关的主要维度，不要求依次执行所有操作符。

验证旨在区分已有竞争解释，深化旨在提供帮助；同一操作符可以服务两者，但必须记录实际任务与帮助条件。尚无用户表达不等于用户未建立联系；先讲解目标机制后的表现不能反推讲解前的理解状态。

`feynman-learning` 在本项目中提供解释、因果缺口、通俗表达、类比边界与迁移观察的参考。2026-10-08，用户明确日常交互需要通过助手的回答自然引导；因此原 Skill 的先解释、追问、重述和练习循环不作为默认执行流程。通用 Agent 优先利用用户已有自然表达，在当前回答中提供适量说明，只有追问有助于原任务时才追问；用户后续自发表达和实际应用作为新的观察。表达困难先保留为待解释现象，不直接判定概念理解不足；回写实际帮助、后续表现与未决解释，由后台综合更新假设。

#### 最近发展区与算法边界

2026-10-08，用户明确 OpenMAIC 的 `zone-of-proximal-development` Skill 更适合本项目的 Prompt 注入阶段。它指导通用 Agent 在获得相关知识与用户状态上下文后，观察用户独立表现、按实际卡点给予帮助，再减少关键提示并通过新表现验证；此定位适用于交互引导与证据反馈，知识搜索、候选发现和来源核查另由相应流程承担。本轮注入时机与交接见 D05，具体交互规则和字段留待设计。

最近发展区关注用户独立能做到什么，以及适当帮助后能做到什么。DistillAI 借鉴按真实卡点调整帮助、区分独立表现与受助表现的原则；日常任务中根据用户自然回应调整解释深度，后续自然出现的新任务可提供应用证据。独立尝试与新任务复核适用于用户明确需要学习或练习的场景；日常交互中不机械安排这些步骤。

Eigma 的 New / Learning / Internalized 页面阶段、复习待办和记忆指标描述学习进展与回忆需求，不直接证明机制理解或迁移。OpenMAIC 的 beginner / intermediate / advanced 是项目教学等级，也不能直接作为每个知识点的掌握状态；提问的负向信号不照搬为“不懂”。

图查询、BKT 与 FSRS 的选型状态见 [T03](../04-knowledge/design.md#data-technology)。

LLM 整理历史表现、帮助与竞争解释并估计理解，程序关联来源和证据；理解判断与教学支持策略分别维护。初版文字状态与假设维护按前文已确认方案执行，完整验证 Prompt 尚未确定。验收方向见 T01（Q02）；剩余交接与验证见 Q09 / Q10 / Q13 / Q16。
