Agent 接入的候选包括 Python + Pi RPC、Node / TS + SDK，以及相应的桥接 / 启动方式；这些内容保留供最终评估，不作为已选择的实现。与接入相关的语言取舍和进程组织届时一并核对。以下接口、任务、权限、文件版本和配置契约属于当前批准内容；批准延后确认的安排不表示已经选定接入或完成正式 Prompt。

## 推荐组合与备选

| 事项 | 推荐方案 | 备选与取舍 |
| --- | --- | --- |
| 后台语言 / Pi（延后确认） | Python 业务后台 + Pi RPC；小型 Node 启动器仅接 MXC SDK，作为候选 | 全 TS + Pi SDK、Python 直接调用 MXC executor 均保留；全部模块 Design 写完后核对工具、模型、取消及隔离需求再选择 |
| Windows 隔离 | MXC ProcessContainer 执行整个 Pi 进程，涵盖文件工具、Shell / Python 和全部子进程 | 自写 AppContainer 需自行承担 Win32 策略与兼容性；srt 公开方案主要面向 macOS / Linux |
| 文件失败恢复 | 独立任务副本 + 基线校验写回，失败丢弃副本 | 原目录实时修改 + 备份覆盖不能可靠保留同期用户修改；若坚持实时可见，需要额外的变更归属 / 文件系统隔离方案 |
| 共用后台 | 一个本地服务提供 HTTP 业务接口；MCP stdio 桥接到同一服务 | 不为 Web / MCP 各运行一个 worker，也不让每次 Hook 各自启动 Agent |
| 并发 | Python `asyncio` 管理队列、RPC 和模型 I/O；一个后台写入任务名额，独立本轮注入名额 | 线程只承担同步文件操作 / 本地 HTTP 请求等阻塞工作；吞吐不足时再增加互不冲突的写任务 |

后台写任务先串行是初版建议，避免共享知识和提交范围互相覆盖；注入有独立执行名额及最高排队优先级，不等待普通任务的模型请求完成。这不要求多个用户 Agent 或多个后台服务。

## Python、Pi 与沙箱怎样连接

本节的 Python / Pi RPC / Node 启动器连接图是候选示例，尚未选定。已认可的安全契约是所有文件工具和命令共用进程隔离、凭证受保护、调用受任务额度约束；接入定稿后以实际框架接口落实这些契约。

```text
Hook / MCP stdio 桥 / Web
           ↓
Python 常驻服务：接收、worker、配置、来源、版本与提交
           ↓ 任务策略、RPC 命令；持续消费 stdout / stderr
受保护的 Node 启动器：MXC SDK spawn / probe / kill
           ↓
Windows ProcessContainer：Pi RPC → 文件工具、Shell、Python、子进程
           ↓ 模型协议请求 + 本任务短期授权
Python 的模型转发入口 → 用户配置的供应商 API
```

Node 启动器只接收后台构造的命令和策略，转接 Pi 标准流及终止控制；不承载 episode、知识、配置或任务语义。它不是新的 Agent。Python RPC 客户端按请求 ID 匹配响应，区分命令接受、模型结束、文件校验和提交成功；绑定固定发行版所支持的结束事件。一个写任务使用一个受控 Pi 会话，业务历史由产品记录保存，不续接个人 Pi 历史。

Pi 以单独 agent 配置目录运行；默认不加载个人 / 工作路径中的扩展、MCP、Skill、模板或可执行配置。仅加载产品提供且受保护的资源；默认资源发现无法完全禁用时，通过显式 ResourceLoader 的 SDK 小桥接替代该 CLI 启动方式，不能带着旁路进入实施。

模型真实密钥留在受保护的后台进程。沙箱中的 Pi 获得指向本机模型转发入口的 endpoint 和仅属于当前任务的短期授权；该授权不能调用配置、启动或文件提交接口。转发入口只处理固定供应商协议、模型和生成路由，不是可传任意 URL 的代理；实际请求前检查状态及剩余额度并记录计数。Pi 自动重试、工具后的继续推理和后台修正都经这个入口，取消或权限撤销同时注销任务授权。

供应商流式响应、工具调用和错误需按实际 API 类型透传或适配。配置必须包含协议类型，不能凭 `base_url` 就认定 OpenAI 兼容；选定供应商后以真实响应验证。自由联网允许命令自行访问外部服务；调用次数预算覆盖本产品使用配置凭证发起的模型请求，不声称能统计任意 Shell 使用其他凭证访问的全部外部模型。

沙箱完整策略包括：任务副本读写、任务输入只读、Pi / Node / Python / Shell 及必要运行库只读、独立任务临时目录读写；真实用户目录、后台状态、版本备份、配置、令牌及其他任务目录不开放。即使它们都位于 `.distillAI` 内，也逐项区分权限，不授予整个数据根读写。已有用户工作路径的授权用于构造副本和后续写回；不在模型上下文中开放系统环境或凭证。

对任意文件工具及子进程都由 OS 执行边界；程序路径校验辅助定位错误。重解析点、硬链接和实际目标身份须验证，不能允许副本链接写到原目录。网络保留已确认的自由联网，并明确本机模型转发所需的 loopback 策略；后台管理服务仍要求独立授权。

启动前 probe 本任务完整策略，记录实际隔离层与警告；不能接受普通 `process`、audit / learning 放行模式或漏掉拒绝路径的降级。部分隔离层可能要求管理员准备；本轮不修改主机 ACL。用户收紧权限时先注销任务授权，再终止整个执行进程树，确认停止后恢复 / 清理；停止未获确认就阻止新写任务，不只发送 Pi 的协作式 `abort`。

本机 Windows 25H2 26200.9457 已达到官方进程隔离最低版本，但这是版本检查；实际后端、私网 / loopback、native 运行库与工具兼容性仍须 probe 和集成验证。Pi、MXC SDK / runtime 和 Node 版本在 Plan 中固定为经核对的发行组合，不以变化中的主分支作为安装基线。

## HTTP、本地材料接管与 MCP / Web

建议服务绑定 `127.0.0.1`，首次启动选择可用端口；受保护的实例文件记录数据根、实例 ID、PID、协议版本、地址及本机授权信息。插件在启动锁内检查实例身份和健康状态，失效实例重新启动；新实例就绪后才发布地址。后台授权与模型任务授权分开，沙箱不能读取前者。

初版 HTTP 可以由标准库 `ThreadingHTTPServer` 的有限路由处理器承担，工作通过线程安全入口交给同一个 asyncio worker；不使用其目录文件服务，不自行编写 HTTP 解析器。限制请求体、验证 Host / Origin、拒绝未知路由及外部页面跨源调用；业务 API 要求本机授权。Web 认证交接由 M08 细化，MCP 采用 stdio 桥和标准协议实现，不向外网开放管理接口。需引入的 Pi、MXC、MCP 组件及版本先列入 Plan 供批准，本轮不添加生产依赖。

| 接口草案 | 核心输入 | 返回 / 错误 |
| --- | --- | --- |
| `GET /v1/health` | 本机授权 | 实例、协议和就绪状态；PID 存在不等于已就绪 |
| `POST /v1/material-notifications` | connector、session_key，格式见 M02 的[通知契约](../02-capture/design.md#material-notification) | `202`：已收到唤醒提示；不上传正文，不是材料持久接收 / 分析完成确认，Hook 不等待它 |
| `POST /v1/tasks` | 去重标识、种类、固定输入引用 / 版本 | `202`：任务 ID / 状态；重复登记返回原任务 |
| `GET /v1/tasks/{id}` | 任务 ID | 状态、次数、结果版本和错误；不存在 `404` |
| `POST /v1/tasks/{id}/cancel` | 原因 | `202`：正在取消 / 恢复；不是已恢复确认 |
| `GET /v1/config` | — | 脱敏配置版本、当前值与待生效值 |
| `PUT /v1/config` | 预期版本、修改值 | 新版本及生效说明；并发修改 `409`，校验失败不写入 |
| `GET /v1/history` | 来源 / 任务 / 记录 ID、分页游标 | 当时输入输出版本及执行记录；M08 补充筛选条件 |

业务模块细化来源和结果 schema；上表随 M01 当前版本批准成为传输层基线。M07 将实时筛选登记为最高优先级任务，通过完成通知取得结果；本方案不新增产品等待时长。其候选版本和 Hook / MCP 交付格式仍由 M07 定义。

材料交接沿用 M02 已确认的本地方案：Hook 同步落盘并保存采集 cursor，发送轻量通知后返回；worker 直接扫描这份持久队列，不上传或复制原文，不设置 `.sent` 或接收确认。通知定位仅允许采集目录内已登记的队列，不能将请求路径直接作为任意文件读取入口。通知失败可由 worker 启动 / 恢复 / 定期扫描补登记，重复通知按接入类型、session key 与持久队列行号范围复用任务；队列长期只追加，同一位置的原文不改写。按 M02 的[初版最小边界](../02-capture/design.md#minimal-capture-boundaries)，不再要求额外源事件 ID 或原 rollout 定位，不承诺不同队列位置间的重采去重。

材料扫描与任务调度轮询沿用已批准的初始 1 秒间隔；通知即时唤醒同一个 worker，空闲时不调用模型。轮询只负责发现 / 登记待办，分析期间固定任务范围；只登记完整有效行，半条尾行等待写入者完成或按 M02 的[写入与尾部恢复](../02-capture/design.md#capture-write-recovery)处理，不提前推进。采集 cursor 和后台处理位置独立，登记任务后崩溃可据持久任务恢复，落盘后尚未登记则由扫描补齐。Hook 通知发送行为由 M02 定义，服务端不以客户端读取 `202` 作为提示或材料的完成条件。

## 文件版本、幂等与崩溃恢复

建议数据根内由程序维护 `tasks/`、`versions/`、`commits/` 与 `workspaces/`，原始队列目录继续由 M02 定义，配置仍为 `config.json`；具体 episode / 知识记录目录由 M03–M05 定义。原始材料沿来源只读访问，不为后台消费另存原文。任务工作目录使用实际副本路径，并记录它对应的原始授权路径；MXC 路径权限不等于透明挂载或路径重映射，不承诺原绝对路径在副本中仍可写。

1. **建立基线**：复制本次开放的产品派生记录与工作目录，记录相对路径、存在状态、文件内容哈希及需要保留的元数据；以独立字节副本保存文件，避免硬链接共享原文件。文件被占用或无法一致读取时重新建立基线或报错，不能跳过后继续宣告可完整恢复。
2. **执行与校验**：全部工具只写任务副本。进程树停止后扫描差异，涵盖任意命令的新增、修改、删除；改名可表达为旧路径删除与新路径新增。校验记录格式、稳定 ID、来源存在、角色及引用关系；M03–M05 定义各自业务校验。空结果允许成功，校验失败可在剩余调用次数内修正。
3. **提交准备**：为每个变更保存前后版本及预期原文件基线，持久写入 `prepared` 清单。后台写任务串行，取得提交与权限锁，确认任务授权仍有效、原文件仍等于基线；用户改过同一文件就报告冲突，不强制覆盖或自动让模型合并。未变更文件不写回。
4. **写回原目录**：Windows 通过文件句柄核对实际目标，在比较与写入期间阻止冲突写入 / 删除；新文件使用排他新建，目录身份及改名同样检查。逐项记录已应用状态，完整持久写回后记录 `committed`。不能只“hash 后 os.replace”留下目标替换窗口，也不声称整批文件对外部编辑器原子可见。平台句柄、冲突和落盘语义在实施验证中核对。
5. **完成及恢复**：只有 `committed` 才推进处理位置；若提交完成但位置 / 索引未更新，重启补完，不重跑模型。执行期间失败或退出，丢弃未发布结果，原文件无需覆盖回退；提交过程中失败，按清单撤销已应用部分。撤销前仍核对文件是本次发布版本，用户又编辑过则进入 `recovery_conflict` 并保留前后版本。新建、删除与改名都有可定位的恢复依据。

内容版本建议按 SHA-256 保存不可变字节，修订清单关联任务与前后版本，避免每次全文复制历史；任务状态 JSON 在程序锁内通过同目录临时文件写入、同步和替换。JSONL 仅用于追加事件，遇到不完整尾行可按最后有效位置恢复，中段损坏报告错误。原子替换不能替代整批提交日志或断电验证。

首次采用完整任务副本，不做依赖文件系统 driver 的写时复制；目录越大准备时间与磁盘成本越高。是否对特定目录缩小范围需明确呈现给用户，不能为了性能默默漏掉允许访问的文件。新链接、特殊设备、NTFS 附加流或不能可靠恢复的元数据变更先拒绝提交并报出具体原因；不把仅内容备份描述为完整文件系统快照。

旧任务的调用计数、实际输入范围和输出版本不改写；后台崩溃后把未完成任务作为中断记录恢复，不仅因进程不在就判定成功。重试沿用原任务额度与基线恢复规则；用户明确重新分析才创建关联的新任务。网络请求的远端影响不属于文件回退。

**已确认的文件修改方式**：2026-10-09，用户认可 Agent 直接使用文件和任意命令工具修改任务副本，成功并通过冲突检查后写回原目录；执行失败丢弃未发布结果，提交失败按版本日志恢复已应用部分，不覆盖用户同期修改。原目录在成功写回后可见，是本次认可方案的行为。

## 普通配置和模型参数

| 配置 | 建议默认 / 校验 | 生效方式 |
| --- | --- | --- |
| `llm.api`、`base_url`、`model`、凭证引用 | 由用户选择供应商；协议与模型明确，凭证只留后台，不默认继承个人 Pi 登录 | 下一项新任务固定配置快照；已有任务保持原值 |
| `llm.parameters` | 不设置通用 temperature / top_p 默认，未设置使用供应商默认；只允许所选协议和模型实际支持的参数 | 新任务生效，保存时校验支持情况 |
| `runtime.max_model_calls` | 建议初始值 16，正整数；包括重试、续推理、修正及该任务的内部模型请求 | 新任务固定额度，崩溃和同任务重试不重置；耗尽走失败恢复 |
| `runtime.poll_interval_seconds` | 建议初始值 1，正数；材料扫描和任务轮询共用，通知可以提前唤醒 | 保存后下一次调度等待应用，不改变已执行任务输入范围 |
| `episode.switch_buffer_turns` | 初始值 3，正整数，按已确认边界观察机制使用 | 新 episode 生效；活跃 episode 保留其创建时参数 |
| `workspace.paths` | 逐项实际路径，添加后默认读写；程序拒绝无效或覆盖受保护执行 / 配置目录的授权 | 新增或扩大用于新任务；收紧立即注销授权、停止受影响任务 |

16 次额度与 1 秒轮询作为本次已认可方案的初始默认值，可通过 Web 配置修改。模型上下文容量与 HTTP / 平台超时是技术约束，不新增产品 token 或时长预算。关闭执行框架不必要的后台模型活动；所有保留的模型请求经过任务计数入口。Pi cache warming 的控制方式随最终接入核对，不存在无任务额度的隐式调用。

配置保存按预期版本检查、类型 / 关联约束校验、持久化新版本再切换；无效配置保持旧值并返回字段错误。生效响应分别展示已保存版本、现行任务仍使用的版本及等待新任务 / 新 episode 的值。权限收紧不等待新任务，重试读取新权限；改动需要重新创建执行环境时不能在原环境中只改内存值。

## 审阅与验证范围

当前版本已获用户批准，任务副本写回不再是待回答问题。Agent 接入方式及关联的语言 / 桥接取舍，等全部模块 Design 写完后共同选择，再收敛正式 Prompt；RPC、SDK 或 Node 启动器继续保留为候选。本轮仅同步批准状态，继续其他模块设计，不创建 Plan 或进入实现。

永久验证保护越界拒绝、子进程不能逃逸、密钥不可读、权限撤销、调用计数不重置、重复通知不重复处理、通知丢失后扫描补登记、处理位置与提交一致、用户独立修改不被覆盖。现有 `tests/test_capture.py` 只覆盖历史采集，不能覆盖这些后台规则。固定发行版兼容、真实 Windows 链接与占用、管理员准备、供应商流式工具请求、注入并发、崩溃窗口及 Web / MCP 认证交接以环境验收记录；本轮仅验证文档。
