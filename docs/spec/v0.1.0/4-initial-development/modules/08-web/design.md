# M08：本地 Web、配置维护与在线编辑 Design

> 2026-10-10 合并来源快照：本文件的 approved 与批准记录表示合并前版本已获批准。后续只维护 [统一 Design](../../design.md)，本文件不再作为当前设计修改入口；正文保留原决定、候选及审批历史。

## 来源、范围与依赖

来源：[已批准 Discussion](../../discussion.md)、[模块路线](../../README.md#module-roadmap)。2026-10-08，用户批准需求与方向基线，并要求按模块分别设计、计划和实施。2026-10-10，用户明确 Web 页面只承担项目配置维护、历史 episode 与知识点等信息查看及在线编辑；此前 Web 复习范围为 `superseded`。随后用户确认下节六项初版行为并授权无其他问题时批准；核对与 M01、M03–M05 的交接后，本文件当前版本为 `approved`，前端技术与必要接入字段按既定顺序后续确认。

本模块负责：项目配置维护、历史 episode 与知识点等信息浏览、跨模块回查及在线编辑。

复用 M01–M07 的业务能力；配置由 M01 执行，episode 归属纠错交 M03，知识与关系编辑交 M04，明确的用户理解判断纠错交 M05。配置、任务状态和历史回查引用 [M01 共用接口草案](../01-runtime/design.md#runtime-contracts)，本模块定义页面与具体查询条件。

每模块遵循 Design 批准 → 同目录 `plan.md` → Plan 批准 → 实施与验证。依赖模块的接口先成为批准基线；可只读或使用合成数据的验证不会被记作完整集成结果。

## 已确认的页面定位

2026-10-10，用户明确本地 Web 的用途：维护项目配置，查看历史 episode、知识点及其关联信息，同时支持在线编辑。现有认知判断、外扩、注入与处理记录继续作为信息查看和来源回查内容；本模块不提供复习入口、推荐复习对象、出题或学习反馈流程。此前提出的“知识 / 历史 / 复习 / 设置”页面组织未获确认，不作为当前设计。

在线编辑沿各记录归属模块的修改、来源与版本规则细化；原始会话来源仍按 M02 只追加、只读回查，不因页面支持编辑而改写历史原文。

## 已确认的初版页面与编辑行为

2026-10-10，用户确认以下六项建议，并授权“无问题就 approve”。本节为当前功能设计；页面视觉、技术实现和必要字段后续沿批准内容细化。

| 决定 | 初版行为 |
| --- | --- |
| 页面分组 | 配置、episode、知识点与关系、处理历史四个入口。认知判断、竞争假设与来源放在关联详情中；外扩、子图、两个列表、筛选与注入记录可从处理历史及相关记录进入。 |
| 在线编辑范围 | 编辑配置、知识点与关系的名称和正文；episode 归属与认知判断提供明确纠错入口，分别交 M03 / M05 处理。原始会话只读，记录 ID、来源及历史版本沿归属模块维护。 |
| 编辑界面 | 常用字段使用表单，正文使用文本编辑区；编辑操作调用既有业务能力。 |
| 保存修改 | 用户显式点击保存，页面展示修改结果。失败或版本冲突时保留输入与错误，由用户处理，不强制覆盖或自动合并。 |
| 历史查看 | 列表、详情、基础筛选和分页；通过关联跳转查看真实来源及当时版本，区分历史值与当前值。 |
| 前端技术 | 随后端与 Agent 接入方案一起确定，复用常驻后台提供页面和接口；本轮不选择具体框架或新增依赖。 |

### 业务交接与页面反馈

配置读取与保存复用 M01 的脱敏配置、预期版本校验和生效规则，分别展示保存结果、当前值与待生效值，字段错误返回到表单。知识 / 关系编辑沿 M04 的 `record_kind / record_id / expected_version / changes / reason` 交接，仅提交本次字段变更；成功后展示实际保存版本及修改结果，不以请求已接收代替业务已保存。

episode 归属纠错保留所指记录及版本、具体错误或来源依据与修订原因，交 M03 按既有修订流程处理，提交后再对受影响记录重分析。认知纠错保留用户提交内容、所纠正的记录版本及来源，交 M05 综合更新；编辑知识正文本身不改变用户理解判断。异步纠错展示关联任务的实际状态及结果，失败保留输入与诊断，保存、版本和恢复沿 M01。

页面提供加载、错误和重试反馈；异步返回不得覆盖用户已更新的路由或输入。历史详情使用已保存的输入输出、配置与 Prompt 版本，不把当前记录冒充当时结果。HTTP / 页面请求错误与后台任务失败分别表达。

#### 本地 Web 配置、历史浏览与模块行为核查

2026-10-08，用户要求 Web 端同时支持参数配置、历史浏览与模块行为核查，以便快速判断哪个模块偏离预期。由现有常驻后台提供简单本地页面及接口，以列表、详情和关联跳转为主，读取实际持久化记录并复用业务能力。

| 视图 | 查看或操作的内容 |
| --- | --- |
| 参数配置 | 模型接入、episode 缓冲及后续明确的运行参数；校验、保存，展示生效状态 |
| episode | 历史交流与原始消息引用、消息归属、缓冲材料、切分和关闭依据及处理状态 |
| 知识点与关系 | 内容、来源、关联 episode 与修订历史；名称与正文按上节确认的表单 / 文本编辑区显式保存 |
| 认知判断 | 竞争假设、用户证据、理解状态及变化依据，区分观察与待验证判断 |
| 外扩与注入 | 搜索发现、相关子图、两个列表、筛选结果和实际交付内容；交付、可观察采用和用户表现分别展示 |
| 处理记录 | 各模块的实际输入范围、输出或修订引用、状态、错误、耗时，以及当时使用的配置与 Prompt 版本 |

回查沿实际来源展开：从知识点进入关联 episode，再定位提取任务当时收到的材料，区分采集缺失、episode 切分偏差和提取偏差；一次注入也能回查候选准备、筛选和交付环节。页面展示已保存的输入输出与判定依据；历史数据要求见 [T03：历史处理记录](../01-runtime/design.md#processing-history)。

配置维护、信息浏览与在线编辑的范围及六项初版行为已确认，采用上节当前决定。具体视觉、前端技术、服务地址、筛选 / 分页参数和 Web 请求表达按后续对齐安排细化。本次仅记录设计，未创建运行配置文件或实现 Web 页面。


## 接入与验证的后续收敛

本模块复用后台业务能力；全模块当前 Design 批准后，先确认 Agent 接入及关联技术，再收敛各业务模块的正式 Prompt，最后分别创建、批准 Plan 并实施。涉及跨模块的变更同步对应 Design，不复制另一模块的权威定义。

验收沿用 Discussion 的 Q02 / Q16。具体永久测试须保护稳定契约、来源和数据完整性或失败恢复；Desktop 触发、Prompt 效果和页面体验以实际使用验收记录。
