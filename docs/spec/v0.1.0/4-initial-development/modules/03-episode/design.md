### D02：episode 构建、边界与维护

状态：`confirmed`。2026-10-09，用户确认下文轮次口径、切换分组条件、response 终止后 30 分钟收尾，以及修订的触发与重分析时机，并随后批准本模块当前 Design。后续细化见前文 Q06 / Q15，历史修正见 [episode 历史记录](../../references/research.md#episode-history)。

#### 定位与完整历史

episode 记录用户围绕某个主题展开的一次连续交流，保留用户表达、Agent 解释、追问、纠正及必要产物的完整历史与来源。它提供可回查、可重新分析的上下文，不以一段 summary 替代历史，也不再等同于一次用户观察或一个 turn 的封装。

数据归属同一用户，由后台 Agent 维护；初版以 session 为交流的外边界，在 session 内切分 episode。同主题的不同交流可以形成不同 episode，跨 session 的续聊通过记录关联表达，不因主题相似自动合并。记录身份、来源范围和主题描述分别承担不同职责，标题或相似度不充当记录身份。

episode 之上的知识提取见 D03，交互与反馈见 D05 / D06，具体字段与状态计算留待设计。完整交流保留角色和帮助条件，不把助手解释直接视为用户掌握证据。跨会话上下文交付仍由 D05 承担，采集缺失也不能由摘要补回。

#### 每个 session 的活跃记录与缓冲切分

每个 session 最多维护一个活跃 episode。后台按源消息顺序处理新增材料：延续当前交流则追加，疑似切换则暂存到待判断归属的缓冲区。一次交付可能包含多个边界；交付批次、Stop 次数或模型调用次数不自动构成 episode 边界。

轮次口径已确认：一条用户消息及其后续助手回应算一轮；同一请求的助手中间文本和最终回应属于该轮，工具摘要作为背景，不单独计轮。该口径用于语义边界观察，不改变 M02 的队列行号与 M01 的处理位置。

主题偏差是信号，最终判断的是交流连续性：追问、纠错、补充必要概念可以延续当前 episode；主题相同但开始新的独立请求或尝试，也可能需要切分。用户要求边界具有可回查的消息依据，不仅依靠“相同主题”或相似度阈值。

缓冲采用连续三轮作为初始观察窗口：这些轮次持续支持切换，且能共同构成同一段新交流时，关闭旧 episode，把缓冲内容确定为新 episode 的开头。确认切换的时刻与实际边界分开，边界回落到新交流的首条消息。例如 `A1 → A2 → A3 → B1 → B2 → B3`，在 B3 确认时，旧记录结束于 A3，新记录从 B1 开始。三轮是观察窗口，不是三次独立投票；窗口参数沿用 M01 的 `episode.switch_buffer_turns` 及新 episode 生效规则。

确认切换时同时判断旧交流是否结束、缓冲材料应该怎样分组。比如从 Python 转到“建 Docker 镜像 → 运行容器 → 挂载目录”，可以形成同一段新交流；“Docker 怎么用 → 明天天气怎样 → 翻译一句话”虽然都偏离 Python，却不能合为一个新 episode。这一连续性判断由 LLM 结合原文完成。2026-10-09，用户要求先参考 RAG 混合检索召回提出计算方法，并接受下文方案作为初版、后续再精细打磨；当前仅融合词项重合和交流连续性，不扩展其他评分维度。

缓冲材料先持久保存原始来源，再暂缓语义归属，不先正式写入旧 episode 后搬运，也不只保存在内存中。如果后续返回原交流，确认只是插曲后将缓冲归入原记录；如果包含多个不同的新交流，不能因均偏离旧主题就合并为一条，需重新判断边界。判断不充分时保留待定归属，不强行切分。

#### 关闭、收尾与分析时机

| 触发条件 | 机制方向 | 仍需核实或细化 |
| --- | --- | --- |
| 缓冲确认交流切换 | 关闭旧 episode，建立新 episode，并落定缓冲来源 | 结果字段；评分权重、阈值与判断规则后续打磨 |
| SessionEnd Hook | 收尾当前 episode，进入待分析状态 | 接入端实际支持、触发语义及可靠性须在 Desktop 验证，本轮未验证 |
| 最新一次 response 终止后达到 30 分钟 | 收尾当前 episode，进入待分析状态；新一轮开始暂停计时，最新 response 终止后重新计时 30 分钟 | 新一轮开始及 response 终止信号与时间的接入 |

SessionEnd 与空闲超时互补；空闲表示本段交流暂时停止，不证明用户已经解决问题。计时起点已确认为最新一次 response 终止时刻，不采用后台收到材料、开始分析或重写文件的时刻；一次回复完成只启动计时，不直接关闭 episode。2026-10-09，用户进一步确认新一轮开始时暂停旧计时，回复或工具执行期间不因旧计时到期而关闭；最新 response 终止后重新计时完整的 30 分钟，不接着扣除上一轮已等待的时间。M02 的正文 `at` 或工具摘要时间不能直接当作 response 终止时间，具体信号接入仍需细化。

收尾时缓冲不足三轮也要判断归属，不为凑满窗口无限等待；有明确新交流依据时单独成 episode，依据不足时保守归入当前记录，并保留判断依据。超时后用户再次继续，采用新建记录并按需关联上一条的方向；延迟到达的旧消息与新的续聊需要在运行契约中区分。

关闭表示本段材料范围已落定，可以生成 summary 并进入后续提取分析；关闭与分析完成是两个状态。关闭结果校验并提交后，worker 按 M01 接续登记知识提取，后续分析交接见 D03。

#### 已确认的修订触发与分析时机

允许修订，包括已经关闭的 episode。修订由具体边界错误或来源纠错依据触发，初版采用两个入口：

- 处理新材料时发现旧边界有误，例如先前缓冲被归入旧 episode，后续消息明确表明它属于一段新交流的开头。
- 用户明确纠错，例如指出两个 episode 实际属于同一次连续讨论。

发现问题后，在本次 episode 维护任务中修正归属并保留来源和修订原因；修订保存、校验并提交成功后，再对受影响的 episode 重新分析。尚未分析过的直接使用修订后的材料。普通续聊仍按已有规则新建并关联上一条 episode，续聊本身不足以证明旧边界错误。

初版不增加定期巡检全部历史、批量重切分或复杂的连锁自动修复。已有提取结果如何结合修订来源更新，在 M04 的知识维护契约中衔接；本模块提供受影响的 episode 与修订版本，不另建恢复系统。

#### LLM 规则评分与程序执行

初版以 LLM 结合上下文判断交流边界，先不引入 SBERT 作为必经环节，也未选定具体模型。SBERT 的文本语义相似度可作为未来辅助信号，但不能单独决定同主题的新尝试或跨概念的连续追问是否应切分。技术参考：[Sentence Transformers 语义相似度说明](https://sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html)。

用户认可通过评分规则 Prompt 让模型输出具体分数，再由程序按规则决定是否进入缓冲或确认切分。模型输入包括当前 episode 的主题与交流目标、最近已确认轮次、缓冲及新增原文，必要时回查更早来源；会话文本是待分析数据，不是评分指令。

评分表达开启另一段交流的证据强度，不把模型分数当作概率。输出方向包括各候选轮次的分数、依据消息与理由，以及缓冲是否构成同一段新交流、边界消息位置。按 M01 已确认方式，Agent 直接修改任务副本中的 episode / 缓冲文件，程序检查评分范围、来源、顺序与状态变化是否符合规则，校验通过后写回；无效变更不作为处理完成的依据，需修正后再推进处理位置。提交和中断恢复沿用 M01，本模块补齐业务校验。候选内容不得先改写旧 episode 的目标，再反过来用新目标消除偏差。

早期讨论曾给出 0～4 档位及连续三轮达到 3 的 Prompt 示例，用于说明流程，不作为定稿量表或阈值。2026-10-09，用户接受下一节的计算与阈值作为初版方案，要求后续再精细打磨；正式 Prompt 仍最后讨论，本次不创建运行 Skill 或训练任务。

后续可保留判断上下文、模型评分与依据、人工确认边界及修正原因，用于迭代 Skill / Prompt 的规则和示例。调整 Skill 与微调模型权重是不同工作；若未来训练模型，不能直接把模型自身评分当正确标签。效果关注误切分、漏切分和边界位置，具体指标计算亦留待下一层。

#### 已确认的初版方案：借鉴混合召回的边界评分

状态：`confirmed`。2026-10-09，用户接受本节作为初版方案，并要求后续再精细打磨；随后批准整个 M03 当前 Design。权重、阈值和判断规则作为当前初始值，后续结合案例调整；尚未实施或验证边界识别效果。

RAG 混合检索融合关键词匹配与语义检索信号，常见方式包括 RRF 排名融合和归一化后的加权求和。参考 [Elastic 混合检索说明](https://www.elastic.co/docs/solutions/search/hybrid-search)、[线性融合公式](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/retrievers/linear-retriever)。这里主要比较候选轮次与一个活跃 episode 的连续性，采用可直接表达强弱的加权分数；不对单个候选使用排名或批次内 min-max 归一化，以免始终排第一被误认为强相关。

初版借用分数融合思路，保留现有 LLM 判断，不新增 BM25 索引、向量库、embedding 模型或 SBERT。词项重合不冒充 BM25，LLM 连续性评分不冒充向量余弦相似度。

**两个输入信号**：

- `K`：词项重合度，范围 0～1。Agent 从当前 episode 已确认的主题、目标及近期原文和候选轮次原文中，各摘取至多五个关键对象或术语，形成集合 `A`、`B`，并附来源引用。词项来自原文，英文转小写、去首尾空白并去重，不增设分词或同义词组件。程序计算 `K = |A ∩ B| / |A ∪ B|`。
- `C`：LLM 给出的交流连续性分，取整数 0～4，必须附依据消息与理由。判断当前轮次是否继续解决原交流目标，包括追问、纠错和必要概念补充；仅主题相同不能证明连续。输入沿用当前 episode、近期原文、缓冲和新增材料，必要时回查，不先用候选内容改写旧目标。

| `C` | 含义 |
| --- | --- |
| 4 | 明确延续当前交流 |
| 3 | 倾向延续，存在可指出的承接关系 |
| 2 | 现有依据不足以判定 |
| 1 | 倾向开启独立交流 |
| 0 | 明确开启新的独立请求或尝试，即使主题相同 |

**初版计算**：先算连续性融合分 `R`，再转换为切换证据分 `S`，越高越支持进入另一段交流。

```text
R = 0.2 × K + 0.8 × (C / 4)
S = 4 × (1 - R)
```

`S` 范围为 0～4，允许小数，不作为概率。0.2 / 0.8 是本项目的起始假设，不是 RAG 通用权重或实测结果；连续性优先，词项重合作辅助。若某侧无法取得有效关键词，省去词项信号，使用 `S = 4 - C`；无法提供有效 `C` 和依据时按 M01 的无效任务结果处理，不用默认分数落定归属。

**初版处理规则**：

- `S < 2`：倾向延续当前 episode。
- `S ≥ 2`：进入或保留待判断缓冲，尚不关闭当前 episode。
- 缓冲达到初始三轮窗口时，结合后续材料共同复核各轮；三轮均达到 `S ≥ 3`，且 LLM 给出它们构成同一段新交流的来源依据，才确认切换。只达到进入缓冲阈值、分组不一致或依据不足时继续待定；收尾时沿用前述不足窗口的归属规则。

这些分数表示与旧 episode 的关系，不能证明缓冲内部构成同一段新交流。已有缓冲遇到一轮低分时仍须共同复核归属，不仅凭该轮分数清空缓冲；后续依据可以改变对先前缓冲轮次的判断，不把三轮变成独立投票。没有活跃 episode 时按新交流创建记录，不需要对不存在的旧 episode 评分。

| 算例 | `K` | `C` | `S` | 分数含义 |
| --- | --- | --- | --- | --- |
| 词项不同，但属于必要概念追问 | 0 | 4 | 0.8 | 延续当前交流 |
| 词项完全相同，但明确开始独立尝试 | 1 | 0 | 3.2 | 支持切换，仍按缓冲窗口确认 |
| 词项部分重合，连续性不确定 | 0.5 | 2 | 2.0 | 进入缓冲，不直接切分 |

上述算例只验证公式行为，`C` 是为说明规则设定的输入，不代表模型能可靠给出该分。后续通过人工确认的连续交流、同主题独立尝试及多主题缓冲案例审阅权重、阈值和 Prompt；不以模型自评分证明方案有效。

#### 持久化方向与未定契约

沿用已确认的用户数据根 `~/.distillAI` 与 JSON/JSONL 方向。episode 属于用户的经历记录；原始采集仍按 AI 工具与 session 管理，后台 Agent 实例不成为数据所有者。

本轮讨论过在数据根下使用 `episodes/<episode_id>.json`，与 `codex/` 采集目录并列，通过来源字段关联 session；这仍是文件布局候选。ID、主题与目标、来源范围、开放 / 关闭状态、边界依据和 summary 等最小记录字段待整理为整体可审阅的示例，不逐项扩展技术选择。完整历史直接引用 M02 长期保留、只追加且行号稳定的队列，保留角色并按来源回查；不复制原文、不增加独立源消息 ID，也不新增轮转或迁移协议。记录版本和历史回查沿用 M01。

接口细化限于三个业务交接：输入新增材料范围、当前 episode、缓冲和收尾原因；校验后的结果说明已归属材料、仍在缓冲的材料及已关闭的 episode；关闭结果交给 M04 知识提取，开放更新交给 M07 安排子图刷新。M03 提供所需记录与版本，子图刷新计数和频率归 M07，任务登记和失败恢复归 M01。
