## 已确认的初版外扩行为

2026-10-10，用户接受以下四项建议。全图扫描、多知识点连接优先、定性排序，以及 M01 / M04 / M05 的职责与契约沿用已有决定，不重新选型。

### 扫描时机与范围

后台周期触发，分批覆盖整个认知地图，保留覆盖进度。近期任务影响扫描先后顺序，同时保留历史知识的扫描机会；全图覆盖不要求每次读取整个地图。具体周期与批量大小作为运行配置，初始值后续确定。

### 重复探索

保留探索对象、结果与未解决问题。有相关新知识、新证据或用户明确要求时再探索同一问题，避免每轮重复搜索；不因上次没有结果就持续重查。

### 核查范围与停止条件

围绕具体主张及关系核查，依据足够或本次问题已覆盖时正常结束，保留仍未解决的缺口。运行预算沿用 M01 的调用次数规则，不另建评分、费用或时长预算体系；预算耗尽与失败恢复沿 M01，不把尚未提交的部分结果视为已保存成果。

### 依据不足的结果与交接

外扩可以形成新知识点、已有节点间的新关系，或已有知识的机制、条件与反例深化。有依据的部分交给 M04 维护，未核实的联系保留为待核查内容及缺口，不作为已成立的联系使用。例如 e 与 a 的联系有依据、与 b 的联系未查清时，可以保留前者，不宣称 e 已连接 a、b。

外部结果保留具体主张与对应来源、核查依据，不能只交接一段摘要。交给 M05 的用户理解判断必须有用户证据，不能由外部搜索结果直接推出；缺少用户证据时沿 M05 表达未知或待验证。知识、关系和认知记录分别由 M04 / M05 维护，保存、版本与任务恢复沿 M01。

### D04：外部搜索与知识扩充

状态：`confirmed`。

用户在此前讨论中提出并于 2026-10-08 重申：已有知识点 a 和 b，c 只与 a 相关，d 只与 b 相关，而 e 同时与 a、b 相关，应优先搜索 e。扩充优先关注能把已有知识连接起来的新知识点，并结合 OpenMAIC 的 Skill 设计完成知识扩充。

2026-10-08，用户确认当前采用后台主动扫描整个认知地图的方向。扫描范围覆盖整个地图，从已有知识点与关系中寻找值得扩充的连接；当前任务和近期 episode 可影响候选优先级，历史知识也进入发现范围。扫描时机、分批覆盖与重复探索采用上节 2026-10-10 确认的行为，具体运行参数与必要字段后续对齐。

| 候选 | 与已有知识的连接 | 用户明确的优先方向 |
| --- | --- | --- |
| c | a ↔ c | 单个已有知识点的扩展 |
| d | b ↔ d | 单个已有知识点的扩展 |
| e | a ↔ e ↔ b | 优先搜索，帮助建立多个已有知识点之间的连接 |

发现 e 的流程：图提供已有节点及连接，后台 Agent 按需读取 a、b 的知识与关系文件，提出可能连接两者的概念或机制，再搜索并核对 e 与 a、b 各自的具体关系。图中尚不存在的 e 需要候选生成与资料发现，不能仅靠遍历现有图得到。

方法分工：`deep-research` 负责搜索与来源核查，`spiral-curriculum` 负责深化维度与排序，UbD 帮助确定理解目标与证据；费曼和最近发展区用于 D05 / D06 的日常引导。源码核对与适配依据集中于 [R06](../../references/research.md#openmaic-methods)。

外部搜索先按以下流程开展：读取已有知识与来源 → 拆分需要核对的具体问题 → 在预算内搜索并选择主要来源 → 阅读原文、记录主张与来源 → 核对冲突 → 依据足够或达到问题覆盖要求后正常结束并保留缺口 → 将有依据的结果交给知识与关系维护。预算耗尽沿 M01 失败恢复，不作为正常交接部分成果的路径。原 Skill 的课程大纲和页面生成步骤不直接作为知识维护步骤；搜索工具与调用次数额度初始值按后续接入与运行配置对齐。

候选流程：后台主动扫描整个认知地图 → 按需读取知识点、关系与用户证据 → 提出连接多个已有知识点的候选并排序 → 外部搜索并核对关系 → 保存知识点及独立关系文件、更新名称图 → 在合适交互中引入 → 根据用户新表现修订认知地图。外部资料形成知识与关系的来源；用户是否建立了这些连接，继续由用户证据判断。

#### 候选知识点的简易优先级

本轮结论：a、b、e 的连接思路与螺旋操作符足以支持初版定性排序。按连接价值、理解增量及当前需要判断候选，结合已有证据考虑先备要求和学习成本；初版可采用“优先 / 候选 / 暂缓”三档，每项保留具体理由和对应操作符，无需先设计加权公式。三档表示预期学习价值，不表示掌握状态或事实核查状态，具体字段与规则留待设计。

| 依据 | 判断问题 |
| --- | --- |
| 连接价值 | 与哪些已有知识点存在具体、有依据的联系，能怎样把它们组织起来？ |
| 理解增量 | 增加新关系、共同机制、抽象模型、表征、复杂度、边界或迁移能力中的哪一种？ |
| 当前需要 | 是否有助于当前任务，或有助于区分一个重要理解假设；先备要求与学习成本是否适合当前条件？ |

任务相关性与学习成本相近时，能通过共同机制连接 a、b 的 e 优先于只扩展单个节点且理解增量较小的 c、d；如果 c 是当前任务必需的先备知识，可以优先于 e。宽泛概念的高连接数不能代替实质解释增量。示例：`e：优先；ADD_RELATION + ABSTRACT；通过共同机制连接 a、b，并解释当前任务中的问题`。后续用户表现用于校准预期学习价值，并按既有假设流程更新理解判断。

主动扫描整个认知地图与简易排序方向已确认；扫描、重复探索、停止条件和部分结果交接采用上节当前决定。具体运行参数、必要字段、搜索工具与正式 Prompt 按后续对齐安排收敛，交互引入由 M07 承接。
